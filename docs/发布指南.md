# 1.0.0发布指南

本指南用于从固定源码生成、验证和分发首版。实际发布结果以对应 tag、Release 和商店页面为准；本地构建不表示已经发布。[验收门禁](验收基线.md)

本仓首版正式标签为 `1.0.0`，与应用和安装包版本一致，不加 `v` 前缀。标签须指向最终验收提交；`SOURCE.json` 的提交和标签、对应源码归档及生产包须来自同一候选。上游 Dictionary 标签、依赖版本和第三方 Action 注释保持各自命名。

## 1. 构建与验证

使用 Node.js 22.12 及以上、Python 3。Chrome 与 Edge 共用 Chromium MV3 业务代码；分别生成明确命名的安装包，便于商店和后续自动化选择。商店身份和 Native 注册分别核验。

```sh
npm ci
npm run format:check
npm run docs:check
npm run verify:connector
npm run typecheck
npm test
npm audit --omit=dev
npm run zip
npm run zip:edge
npm run verify:manifest
npm run verify:manifest:edge
npm run verify:store-packages
npm run test:browser
npm run test:connected
npm run verify:store-packages
```

`.output/chrome-mv3/` 与 `.output/edge-mv3/` 是两种解压扩展，ZIP 位于 `.output/`。`verify:store-packages` 核对 ZIP CRC、每个文件与生产目录的 SHA，以及两端完整生产字节一致，生成 `store-packages.json` 和 `SHA256SUMS`。来源记录包含源码提交与工作区是否有未提交修改；正式 CI 产物必须来自干净源码。

同一候选的两端生产字节完全相同时，可以共用 Chromium 行为测试结果；这不代表已经在正式 Edge 验收。若两端输出不同，等价门禁会失败，应分别验证差异，不能改名复制来绕过。改变分片编码或运行时解析方式也是生产变更，必须对新候选重新执行完整独立 UI 和真实连接，不能沿用旧包成绩。

包内只提供 Dictionary 0.0.3 Lite Text；Core 是按需增量，Full 仅由 Desktop 使用。不得混入个人库、profile、原始报告、测试 fixture、本机 Native 注册或私人提交材料。

WXT 的 `zip` 会重新构建，应先生成 ZIP，再对同一生产字节运行 UI 与真实连接。归档时直接复制已验收的包，核对 ZIP CRC、每个文件的 SHA 和生产集合摘要；若重新构建或改变生产字节，须重新验收。

生产目录递归检查只允许根目录的 `manifest.json`；词典数据清单为 `dictionaries/core/dictionary-manifest.json`。商店安装包只在最外层使用 ZIP 压缩，随包词典分片使用普通 JSON/JSONL，不再内嵌 gzip 等压缩文件，避免 Edge 包校验拒绝。准备脚本替换旧生成目录，保留词典内容与上游来源摘要；数据清单核对实际展开后的资产。`verify:store-packages` 同时拒绝安装包内部的压缩档案。

按需下载的 Core 增量仍使用上游的压缩发行格式，经摘要校验后在本地解析；它不是扩展安装包的内嵌文件。单独分发的源码 `tar.gz` 也不放入扩展 ZIP。

构建检查包括：manifest 版本 1.0.0、最低 Chromium 142、七项 API 权限和 HTTP/HTTPS 网站权限、冻结合同与声明一致、公开词包大小与摘要一致，以及完整许可。协议版本、来源和摘要从 `lib/connector/contracts/` 读取，不在维护指南中硬编码某次候选值。

## 2. 完整发行物

每次准备发行使用新的目录，依据配套来源清单选择物料，不混用不同构建的源码、扩展和测试报告。

```text
.output/github-release/
├── leximeet-browser-1.0.0-chrome.zip
├── leximeet-browser-1.0.0-edge.zip
├── leximeet-browser-source-1.0.0.tar.gz
├── LICENSE
├── SOURCE.json
├── store-packages.json
└── SHA256SUMS
```

固定最终提交后，使用完整 `git archive --format=tar.gz --prefix=leximeet-browser/ <commit>` 生成对应源码，包含代码、测试、构建脚本、依赖锁、文档和许可，不含 Git 历史、缓存和个人资料。不能只打包部分业务目录或拼装未提交工作区。扩展 ZIP、根 LICENSE 和完整对应源码共同分发。[第三方与许可](第三方与许可.md)

`SOURCE.json` 记录本标签源码提交、协议版本/摘要、词包锁、生产集合摘要和独立 CI 范围；`store-packages.json` 保留原检查产物证据。真实连接的 Browser/Desktop/Core 组合由独立连接工作流记录，不把独立结果当作连接或正式 Edge 实机验收。`SHA256SUMS` 校验扩展、源码、LICENSE 和 SOURCE，不包含自身。下载后再次核对大小与 SHA。

## 3. 发布检查

- [ ] 固定源码和运行字节，工作区变更归属已确认。
- [ ] 公开文件、Git 历史、依赖和数据许可已检查；私人操作资料位于仓外。
- [ ] 基础、独立 UI 和真实连接门禁通过，人工验收及目标平台边界明确。
- [ ] 扩展、对应源码、许可、来源和校验文件齐备。
- [ ] 在宣布支持的正式浏览器检查扩展 ID、网站权限和 Native 安装、撤销与连接。
- [ ] 需要远端 CI 证据时运行对应工作流，记录 run URL 和源码提交。
- [ ] 经维护者确认后创建 tag、推送和发布；核对公开下载资产。

首版不迁移 0.x/rc 测试库。首次发布没有前一正式包；之后的版本升级按[兼容政策](版本与兼容.md)保留已有资料。源码链通过不替代实际桌面发行包验证；一个操作系统的结果不外推其他平台。

## 4. GitHub 与 Gitee

[GitHub](https://github.com/leximeet/leximeet-browser) 和 [Gitee](https://gitee.com/leximeet/leximeet-browser) 是平级的源码与协作入口。两平台的同一版本使用相同源码提交、同一个本地注解标签以及同一批 ZIP、源码、许可与校验文件；不要为第二个平台重新构建，也不要分别创建同名标签。上传后分别下载核对 SHA-256，某平台尚未发布时应明确标注。

最终验收通过后才创建 `1.0.0` 标签；在标签未公开前可以继续修改候选，不能把 package.json 版本号当作发布证据。标签一经公开便不移动，后续修复使用新版本。推送前检查两端 main，审阅并整合平台间的新贡献；只推送本轮 main 和版本标签，不推送本地开发历史，不使用 `--all`、`--mirror` 或强制覆盖。

当前 `.github/workflows` 在 GitHub Actions 执行，不会因 Gitee 有同名仓库而自动运行。固定提交上的本地测试、GitHub run、正式浏览器商店审核和两平台 Release 下载分别核验。词典下载仍采用锁文件中的 GitHub Dictionary Release；Gitee 源码托管不改变实际联网范围。

推送、创建 Release 和商店提交均由维护者明确授权。Chrome / Edge 商店的扩展 ID 与签名身份按商店实际分配，不由 Git 托管平台决定。

## 5. 浏览器商店

首次提交通过 Chrome Web Store 或 Edge Add-ons 后台上传扩展 ZIP，上传包内只允许根目录的一份 `manifest.json`。公开隐私政策、准确的功能与权限说明、图标和合规截图应与实际版本一致。[隐私政策](隐私政策.md) · [隐私与权限](隐私与权限.md)

具体后台填写表、账号配置、凭据和本次宣传物料放在仓外发布资料目录，不作为产品源码文档。商店审核结果和正式扩展身份确认后，再更新公开安装入口。

1.0.0 已发布，公开入口如下：

- Chrome Web Store：[词遇-LexiMeet](https://chromewebstore.google.com/detail/%E8%AF%8D%E9%81%87-leximeet/ffpencpinagmaiggednonfipgfmgmcdn)。扩展 ID：`ffpencpinagmaiggednonfipgfmgmcdn`。
- Microsoft Edge Add-ons：[词遇-LexiMeet](https://microsoftedge.microsoft.com/addons/detail/%E8%AF%8D%E9%81%87leximeet/lokiongmifeccfecjjcmcdpihpohfmnc)。商店列表 ID：`lokiongmifeccfecjjcmcdpihpohfmnc`。

Edge 的商店列表 ID 是加载项页面地址中的公开标识，不是 Partner Center 的 Product ID（GUID）。`EDGE_PRODUCT_ID` 仍只放在 Actions 变量里。后续版本在新的审核结果确认后再改这些地址。

## 6. GitHub Actions 上传 Edge 草稿

首次发布仍在 Partner Center 创建产品、上传 ZIP 并填写资料。微软的更新 API 面向已发布扩展，不创建产品或填写商店文案。首发后可使用 `Upload Edge draft package`；它只上传新草稿包，维护者在后台提交审核。[微软 API 说明](https://learn.microsoft.com/en-us/microsoft-edge/extensions/update/api/using-addons-api)

### 配置一次

1. Partner Center → Microsoft Edge → Publish API：启用新体验并创建凭据，取得 **Client ID** 和 **API Key**；注意密钥有效期。不要使用旧版 Client Secret / Access token URL。
2. GitHub 仓库 → Settings → Environments：创建 `edge-store`，部署分支只允许 `main`，按仓库能力设置维护者审批。
3. 在这个 Environment 配置下表。也可使用仓库的 Settings → Secrets and variables → Actions；不要把值写入源码、workflow 或日志。

| 类型     | 名称              | 内容                                                   |
| -------- | ----------------- | ------------------------------------------------------ |
| Secret   | `EDGE_CLIENT_ID`  | Publish API 的 Client ID                               |
| Secret   | `EDGE_API_KEY`    | Publish API 的 API Key                                 |
| Variable | `EDGE_PRODUCT_ID` | 扩展后台的 Product ID（GUID），不是 Store ID 或 CRX ID |

### 每次更新

1. `main` 的 `Browser standalone CI` 完整通过，保存 run ID 和 40 位源码 SHA；其 `browser-store-packages` artifact 包含 Chrome/Edge ZIP、摘要及来源。
2. 对同一 Browser SHA 运行 `Browser real Desktop connection`，输入匹配的 Desktop/Core 来源，取得成功 run ID。
3. Actions → `Upload Edge draft package` → Run workflow，选择 `main`，填入两个 run ID 和该 SHA，确认产品已首次发布。
4. 工作流检查同仓、同一源码、完整成功的两个门禁，下载原 CI 安装包并验证摘要。只在最终上传步骤读取密钥，使用 API v1.1；没有重新构建或自动发布。
5. 显示草稿包处理成功后，到 Partner Center 核对文案、截图、隐私和版本，再手动提交。上传失败、超时或状态未知时先检查后台，避免重复上传。

Artifact 保留 14 天，过期后需重新构建并验收固定候选。连接工作流仍为 Chromium + 真实 Desktop，正式 Edge、扩展商店 ID 和 Native Host 授权需另行人工核验。Chrome 当前保留手动商店上传，不能把 Edge 工作流理解为两商店自动发布。

## 7. 标签触发 GitHub Release

维护者批准正式版本后，推送单个注解标签 `1.0.0`。`Browser standalone CI` 先运行格式、合同、类型、全部单元、两份 ZIP 构建与等价检查，以及完整独立 Chromium UI；通过后发布任务下载原 CI 附件，使用 `scripts/package-github-release.mjs` 核对版本、干净来源、大小和摘要，归档标签对应完整源码。

检查任务只读；最终发布任务使用 contents:write，附件完整上传到草稿后才公开。main / PR 不创建 Release。此流程不提交 Chrome/Edge 商店，也不上传 Gitee；另一个平台应复用这批原样附件。已公开标签或版本不覆盖，后续修复使用新版本。[本版发行说明](版本/1.0.0.md)
