## SDK 与自有源码的边界

`ContentScriptContext` 是 WXT 的正常 SDK 依赖。WXT 为内容脚本生成入口，创建上下文并负责失效清理，构建器再把所需代码合并进插件 JS；项目没有把这个类手工复制到 `lib/`、`page/` 或 `ui/`。[WXT 官方说明](https://wxt.dev/guide/essentials/content-scripts.html#context)

| 位置                                                                         | 内容与用途                                  |
| ---------------------------------------------------------------------------- | ------------------------------------------- |
| `entrypoints/page.content.ts`                                                | 自有入口：定义网页匹配和阅读界面挂载        |
| `node_modules/wxt/dist/virtual/content-script-isolated-world-entrypoint.mjs` | WXT SDK：导入并创建 `ContentScriptContext`  |
| `node_modules/wxt/dist/utils/content-script-context.mjs`                     | WXT SDK：上下文失效、事件和导航生命周期     |
| `.output/chrome-mv3/content-scripts/page.js`                                 | 生成产物：包含自有逻辑和实际使用的 SDK 代码 |

自有运行源码主要为 `entrypoints/`、`lib/`、`page/`、`ui/`，另有 `wxt.config.ts` 构建配置和 `env.d.ts` 类型声明。`lib/connector/contracts/` 是协议消费物料，保留其来源。`public/` 的品牌、图标和词包属于运行资源，分别保留声明；`package.json`、锁文件和构建脚本用于重现构建。`tests/` 是测试材料，`node_modules/` 是依赖，`.wxt/` 与 `.output/` 是生成目录。

正常 SDK 打包也必须保留许可证。发布包的 `THIRD_PARTY_NOTICES.txt` 覆盖 Vue、fzstd、WXT、浏览器 API facade，以及 Vite/Rolldown 生成辅助代码的上游来源；构建检查核对版本、版权声明和实际随包文件。公开发行的完整对应源码保留锁文件、构建脚本、测试与许可，不以部分业务目录代替完整源码。
