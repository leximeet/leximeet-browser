# 开发指南

## 环境和构建

需要 Node.js 22.12+，依赖由 npm 锁定；CI 使用 Node 22。双端源码环境另需 Desktop/Core、JDK 21 与 Maven。测试浏览器使用 Playwright 安装的专属 Chromium，不使用日常 profile。

```sh
npm ci
npx playwright install chromium
npm run fetch:dictionary -- --with-core
npm run build
npm run verify:manifest
```

词包由`dictionary-text.lock.json`固定，不跟随 latest。优先读取相邻的`leximeet-dictionary/dist/v0.0.3`，缺少时下载固定 Release 并核验。可用`LEXIMEET_DICTIONARY_RELEASE_DIR=/path/to/v0.0.3`指定缓存。生成资产保存在忽略目录`public/dictionaries/core/`；`core`仅是资源路径，实际内置的是 Lite。

当前个人库使用 `leximeet-browser-personal/4` / IndexedDB 4。预发布旧profile不转换；使用独立lab或新测试profile。

本地 `lib/connector/contracts/` 是完整冻结合同；`snapshot.json` 保留上游路径与来源，文件按 basename 存放。修改消费来源时必须同步全部17份规范、Schema、方法和参考样例，禁止仅修改版本号或照抄对端摘要。`npm run verify:connector` 独立核验20份文件、JCS配置/规范摘要与正文覆盖；构建也执行同一检查。规范字节不经 Prettier 重写。

本地热更新为`npm run dev`。完整门禁和失败诊断见[测试与验收](测试与验收.md)。

## 代码规范

```sh
npm run format          # Prettier3.6.2格式化源码、测试与文档
npm run format:check    # 仅读取检查，CI门禁
npm run verify
```

Prettier 版本固定，不自动改变业务、排序类名或更新依赖。冻结协议、共享向量和词典资产明确列入忽略范围，保留原字节；生成的构建产物、缓存、日志和 profile 不格式化，也不提交。在关键边界添加中文注释，说明目的、失败情形和生命周期，避免逐行翻译代码。

新增模块优先沿应用服务、仓库、纯规则和设备适配分层。与 Desktop 的共同规则通过共享向量核对；修改协议时，先更新 Protocol 并核验正式快照，不能只替换版本号。当前生产数据由可信服务判题和写入，UI 不能上报分数或 FSRS。

## 独立隔离环境

```sh
npm run lab:browser
# 外网不可用时仅使用本轮本地文章
LEXIMEET_LAB_URL=local npm run lab:browser
```

人工 lab 会显示窗口，首次启动会打开内置教学及 Node.js 英文文档；外网访问失败时改用本地文章。每次启动都使用新 profile，关闭浏览器或按 Ctrl+C 只清理本轮进程、端口与资料。需要保留真实个人资料时，请手工加载正式构建，勿放在临时 lab 中。

## 双端环境

目录布局：

```text
workspace/
├─ leximeet-desktop/
├─ leximeet-desktop-core/
└─ plugin/leximeet-browser/
```

推荐从Desktop运行`bash scripts/test-desktop.sh --connected`，自动准备隔离Node/JDK/Chromium和随包应用。仅检查用`--connected --check`。

Browser源码联调入口（Desktop已安装锁定依赖）：

```sh
npm run lab:connected
npm run lab:connected -- --check
npm run lab:connected -- --no-build
```

实际启动时会验证双方候选、协议摘要、Core、Native 来源和就绪状态；声明检查不等于业务验收。验收脚本匹配固定组合，以绑定证据来源；产品正式 hello 按 major、最低服务版本与必需能力和方法协商，不要求两端交付摘要相同。在交互终端输入`help`可查看`stop`/`restart`的用法，用于控制本轮 Desktop；停机后重开 Browser 不会自动启动 Desktop。邀请必须由用户在浏览器确认窗中接受。

## 提交与交接

`main` 保存可发布主线，开发记录分支保留开发历史。只暂存本轮文件，运行对应测试、更新 CHANGELOG 并使用中文提交说明；个人提交备忘放在本地忽略的 `git-commit-message.txt` 或仓外。推送、PR、tag、商店或 Release 均需要明确授权。

交接说明应写清最终行为、接口和模型差异、测试命令与未验证平台；过程日志不进入公开仓库。截图和报告不得包含个人库、真实凭据或私人绝对路径。
