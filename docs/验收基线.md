# 1.0.0验收门禁与边界

本页定义可复验的发布标准，不把某次开发候选的结果当作当前版本的证明。具体源码、合同、安装包摘要与实际结果随对应发行物记录在 `SOURCE.json`、`SHA256SUMS` 和发行说明中。[测试方法](测试与验收.md) · [发布指南](发布指南.md)

## 必须检查

| 门禁       | 通过条件                                                                                        |
| ---------- | ----------------------------------------------------------------------------------------------- |
| 公开源码   | 无凭据、个人数据库、私人路径和操作备忘；许可、来源、依赖锁和构建说明齐全                        |
| 协议快照   | `npm run verify:connector` 校验本端冻结规范与摘要；构建声明和运行协商保持一致                   |
| 基础检查   | 格式、文档引用、类型、单元与生产 manifest 全部通过                                              |
| 独立使用   | 原样生产包完整 UI 套件通过；教学、设置、词库、采集、六种练习和整浏览器重开正常                  |
| 桌面连接   | 同一 Browser 生产包通过真实 Native→Desktop→Core；确认、三入口采集、封存恢复、失联停写与撤权正确 |
| 实际发行物 | ZIP 的内容与验收生产文件逐项一致；完整对应源码、根 LICENSE 和摘要配套                           |
| 人工复核   | 在宣布支持的平台确认安装、网站权限、原生侧栏、声音与通知；人工结果和自动结果分别记录            |

真实 UI 与连接套件要求零失败、零跳过、零重试；源码连接、实际桌面应用包连接和目标浏览器安装是不同验证层，按实际执行范围说明。测试只清理自己拥有的进程、profile、端口和 Native 注册。

## 资料和版本

首版独立资料格式为 `leximeet-browser-personal/4`，使用 IndexedDB 4 和六个正式 store。0.x/rc 测试库不迁移；未知格式拒绝并保留，不能清空旧库来制造通过。首版须验证新库、事务、整浏览器重开和连接封存恢复。

首次发布没有前一正式版本，不将旧格式候选算作正式升级验收。存在可信的同格式前包时，可另做同 profile 包替换；1.0.0 发布后的版本升级必须验证真实前一正式包和已有事实、稳定 ID 的保留。[兼容政策](版本与兼容.md)

## 证据边界

- 历史通过数不能证明改变后的生产包；源码、合同或运行资产变更时重新验证。
- 无头 Chromium 结果不自动证明正式 Chrome/Edge 或其他操作系统已验收。
- 本地构建和本地测试不证明远端 Actions、签名、公证、商店审核或已发布。
- 静态截图不证明事务、音质、通知横幅或交互时序。

原始日志、trace、完整候选来源与私人操作材料保存在仓外；公开发行说明只保留准确结果、必要摘要和未验证范围。
